# 对照表核对方法

目标：周报里的每一行，都能说清楚为什么填到 PSI 的这个代码。**不看上周写的什么，只看证据。**

## 一、一个代码是怎么组成的

`PSI 代码 = 项目号 + 运存 + 存储`，比如 `P154+128` = 项目 P15（Redmi 15C 5G）+ 4 + 128。
注意 `P196+256` 的内存是 6+256，不是 96+256。

新旧代码是同一个产品：Q16 = MOSCOW，Q16U = BRUSSELS，Q16P = MOSCOWP。填 PSI 用新代码。对照表的最后一列“旧代码”和“代码别名”页都可以查。

## 二、四种证据，按可靠程度排序

| 顺序 | 证据 | 从哪里看 | 能确定什么 | 注意 |
|---|---|---|---|---|
| 1 | 运营商原始文件的名称和编码 | 周报原件（Orange 还有 BSCS 码） | 型号、内存 | 名称可能截断；转手的汇总表不算原始文件 |
| 2 | TTL ID 表 | EAN、SKU、Name → CRR1 | 型号 → 代码 | 新品常缺型号；有个别错行 |
| 3 | PSI 的行 | E 列项目名称、G 列项目号、H 列内存 | **这张表有没有这一行** | 名称有错（O19 叫 Redmi 14 5G）；不同表可能不一样 |
| 4 | 同型号的其他物料 | TMO 物料号 T117**040**：前面是型号，后三位是颜色或版本 | 同型号应该同代码 | 只作旁证 |

**上周的 CODE 列不算证据。** 只能用来对比，发现不一样时再查原因。

## 三、核对一行的步骤

1. **先判断要不要计入。** 手表、耳机、充电器不计入；DEMO、SAMPLE、Outlet、reSTART、大写 CR、Orange 的 `E.` 不计入。`bi`、`cz` 这类颜色不影响。
2. **拆出型号和内存。** 去掉品牌、颜色和 `DS`；把 `RedNote`、`RedNo`、`RM Note` 统一成 Redmi Note。
3. **逐字比型号，以下都是不同产品：**
   - 有没有 5G：Redmi 12 / Redmi 12 5G
   - 有没有 Note：Redmi 12 / Note 12
   - 后缀：15 / 15C，Pro / Pro+ / Pro Max
   - 没写品牌的：Plus 的 `13 5G` 是 Xiaomi 13，不是 Redmi 13
   - 平板：WiFi / 5G、带键盘或笔的套装
4. **查 TTL。** 用 EAN 或 SKU 最准；只有名称时，按型号 + 内存查 CRR1。
5. **查 PSI。** 在对应运营商的 sheet 找这个代码。
6. **下结论：**

| 情况 | 结论 |
|---|---|
| TTL 和 PSI 指向同一个代码 | 填这个代码 |
| TTL 有代码，但这张 PSI 没有这一行 | **不填** |
| 只有 PSI 有（新品 TTL 还没更新） | 填，但原始名称和 PSI 名称要逐字对上 |
| 两边不一样，或一个名称对应多个代码 | **问负责人，不要猜** |
| 两边都没有 | 新品或老品：有数量的告诉负责人，看要不要在 PSI 加行 |

## 四、来了新货或新表怎么办

**新型号：**

1. 跑工具，看报告的“未匹配”。
2. 查一下该填什么：

```bash
.venv/bin/python -m tools.audit_mapping --name "Xiaomi Redmi 15C 5G 4/128GB Czarny" --sheet TMO
```

3. 确认后，在 `mapping/mapping.xlsx` 加一行（source、key、psi_code、category、product_name）。
4. 重新导出对照表：

```bash
.venv/bin/python -m tools.export_mapping
```

**新的周报格式或新运营商：**

1. 看表头，确定哪列是识别码、名称、SO、库存，写进 `docs/各家周报列说明.md`。
2. 在 `config/sources.yaml` 加一段配置。
3. 拿至少一周的手工结果和工具对数，一致后再用。

**PSI 改了行或 TTL 更新了：** 重新导出对照表，先看“待你确认”这一页。

```

```

```bash

```

## 六、对照表每一列的意思（`mapping/PSI码对照表.xlsx`）

| 列 | 意思 |
|---|---|
| PSI 代码 | 要填的代码，只有“计入”的行才有 |
| 是否计入 | 不计入的原因 |
| 核对结论 | 一致 / 人工确认 / 冲突 / 漏映射 / 排除待查 / 无法验证 |
| 依据 | 这个结论是怎么来的 |
| 旧代码 | BOC、促销表的写法（Q16 系列），没有旧代码的留空 |

`待你确认` 页里的问题解决之前，那几行的数不要当成最终结果。
