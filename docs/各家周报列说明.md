## POCO 单独发的表：先看主表里有没有

规则（2026-11-12 确认）：客户把 POCO 单独发一份时，先看这家的主表里有没有 POCO 型号。**有就不合并**（免得算两次），**没有才把 POCO 表加进去**。工具每周自动判断（名称带 POCO，或同一个物料码 / EAN 出现在主表里），跳过时报告会写"主表里已经有 POCO 型号，这份 POCO 表不再合并"。

| 客户 | 单独的 POCO 表 | 主表里有 POCO 吗 | 处理 |
|---|---|---|---|
| AB | `xiaomi_poco_sell_through_…`、`xiaomi_poco_stock_…`（W42 起） | 没有 | 合并 |
| ALSO | `ALSO_Reporting_POCO_…`（W45 起） | 没有 | 合并 |
| MSH | `Raport Xiaomi POCO W{N}`（只在 W22 发过，按月、按门店拆分） | 有：Total 页先是 POCO 480002533 一段，再是 XIAOMI 480002320 一段 | 不合并，工具不读这份 |
| IM、EURO、MEX、X-KOM、KTR、MAX、GG、ROLV、Plus | 没有单独的表 | 有 | 照常用主表 |
| Play、TMO、Orange、Auchan | 没有 | W44 主表里没有 POCO 行 | — |

## 为什么"选这一列"

PSI 里每个 KA 只要两个数：
- **SO**：这一周卖给消费者多少台；
- **Channel Inventory Actual**：周末时这个 KA 手里还有多少台。

所以选列的原则只有一条：**找"本周销量"和"周末库存"**。客户给的其他列，大多是这两个数的拆分或中间量：
- 拆分：门店、仓库、B2B 分开报；
- 中间量：期初库存、到货、铺货。

需要判断的只有"库存要不要包括仓库"。PSI 的 Channel Inventory 指整个渠道里的库存，KA 自己仓库里的货也要算。Orange、Plus、Auchan 都按这个口径（Auchan 确认按门店 + 仓库，W10 起 PSI 漏了仓库，要补算）。

## Orange 的 "E." 开头型号

W11–W41 的原始文件里一共出现过 3 个，物料号和正常型号不同，BSCS 代码也多了 `E_` 前缀：

| 物料号 | 名称 | BSCS 代码 | 库存变化 |
|---|---|---|---|
| 1100035827 | E.XIAOMI REDMI 15C 4/128GB CZARNY | E_XIA_RED15C_128_DS | W11 起门店一直是 585–593 台，几乎不动，铺货量一直是 0 |
| 1100038697 | E.XIAOMI REDMI A7 PRO 4/128GB CZARNY | E_XIA_RED_A7P_128_DS | W34 中央仓 300 → W35 一次性铺到门店 300，之后一直 300 不动 |
| 1100035687 | E.XIAOMI REDMI NOTE 14 PRO+5G 12/512 CZA | E_XIA_N14PP5125G_ES | 258 台缓慢减到 0（W41 已经没有） |

对照：正常的 Redmi 15C 物料号是 1100035668（XIA_RED15C_4_128_DS），Redmi A7 Pro 是 1100038533。

**结论（2026-11-02 已确认）**："E." 是门店展示机，不计入 SO 和库存。当时的判断依据：
- 一次性铺到门店后数量就不再变动；
- 几个月里从来没有销量。

Jet 的表也没有算它们，和 TMO 的 DEMO 不计入是同一个道理。
